# Часті запитання (FAQ)

## Встановлення та налаштування

### Q: Яка версія Arduino потрібна?
**A:** Проект використовує Arduino framework для ESP32 через PlatformIO. Специфічна версія:
```
framework-arduinoespressif32 @ 3.20017+
```
Встановіть автоматично через PlatformIO.

### Q: Чи можу я використовувати Arduino IDE замість PlatformIO?
**A:** Не рекомендується. PlatformIO краще управляє залежностями. Однак, можна:
1. Встановити всі бібліотеки через Arduino Library Manager
2. Налаштувати I2C pins вручну
3. Забезпечити LittleFS підтримку

### Q: Який USB кабель потрібен для ESP32?
**A:** Використовуйте **USB-C или Micro-USB** (залежить від вашої дошки).
- Переконайтесь що це **data кабель**, не тільки для заряджання
- Вам також потрібна мікросхема CH340/CP2102 для серійного з'єднання

## Апаратне забезпечення

### Q: Чи потрібна мені PCA9685 або можу я використовувати PWM напряму з ESP32?
**A:** PCA9685 мається на увазі для більшої стабільності та кількості каналів.

Для прямого PWM ESP32:
1. Відмініть `#include "PCA9685.h"` у `LightControl.cpp`
2. Замініть на прямі GPIO PWM
3. Обновіте пінси в конфігурації

### Q: На скільки каналів я можу розширити систему?
**A:** З однією PCA9685 - до 16 каналів. Для більшого:
- Додайте другу PCA9685 з різними I2C адресами (0x40-0x7F)
- Модифікуйте `LightControl.cpp` для управління кількома дошками

### Q: Чи працює з іншими температурними датчиками?
**A:** Проект оптимізований для **DS18B20**. Для інших:
1. Встановіть відповідну бібліотеку
2. Модифікуйте `TemperatureControl.cpp`
3. Оновіть API endpoint

Приклад для DHT22:
```cpp
#include "DHT.h"
DHT dht(GPIO_NUM_4, DHT22);

float getTemperature() {
  return dht.readTemperature();
}
```

## WiFi та мережа

### Q: Пристрій не приєднується до WiFi. Що робити?
**A:** Перевірте по черзі:

1. **Перезагрузіть пристрій:**
   ```bash
   pio run --target upload
   pio run --target monitor
   ```

2. **Перевірте SSID та пароль:**
   - Немає пробілів в кінці
   - Правильна мова введення
   - Менше 32 символів

3. **Увімкніть AP режим (точка доступу):**
   - Підключіться до `AquaSmart_XXXX`
   - Перейдіть на `192.168.4.1`
   - Налаштуйте WiFi

4. **Перевірте інтернет:**
   ```bash
   # На іншому пристрої
   ping 192.168.1.100
   ```

### Q: Як змінити AP пароль для режиму AP?
**A:** Відредагуйте `AquaWiFiControl.cpp`:

```cpp
WiFi.softAP("AquaSmart_XXXX", "your_password");
```

### Q: Пристрій відключається від WiFi кожні 5 хвилин
**A:** Це може бути:
- Слабкий сигнал WiFi - переміщуйте ближче до маршрутизатора
- Конфлікт IP адреси - перезагрузіть маршрутизатор
- Проблеми з бібліотекою - оновіть `AsyncTCP`

## Освітлення та PWM

### Q: Яскравість не змінюється гладко, виглядає как "стрибками"
**A:** Проблема в гама-корекції. Перевірте:

```cpp
// LightControl.cpp
float gammaCorrected = pow(normalized, gammaCoefficients[channel]);
```

Значення гама за замовчуванням: **2.2**. Спробуйте:
- Зменшити до 1.8 для гладкості
- Збільшити до 2.5 для контрасту

### Q: Один канал не світить
**A:** Послідовність перевірки:

1. Перевірте дріт та LED
   ```cpp
   setChannelBrightness(channel, 255); // повна яскравість
   ```

2. Перевірте адресу PCA9685 (за замовчуванням 0x40)
   ```cpp
   // Скануйте I2C пристрої
   pio run --target upload
   ```

3. Перевірте файл конфігурації (`EEPROM`)
   ```cpp
   initEEPROM();
   ```

### Q: Як включити PWM на більш високій частоті?
**A:** Відредагуйте `LightControl.cpp`:

```cpp
pwm.setPWMFreq(1000); // Герці (за замовчуванням 1000)
```

## Розклади та MQTT

### Q: Розклад не запускається в час
**A:** Перевірте:

1. **Час системи правильний?**
   ```
   GET /api/status → time
   ```

2. **Дата відповідає формату?**
   ```json
   {
     "date": "2026-01-27",  // ✅ Правильно
     "schedule": [...]
   }
   ```

3. **RTC бага?**
   - Перевірте батарею на DS1307
   - Синхронізуйте з NTP: `syncTimeWithNTP("pool.ntp.org")`

### Q: MQTT не підключається
**A:** Перевірте:

1. **MQTT сервер доступен?**
   ```bash
   telnet mqtt.example.com 1883
   ```

2. **Облікові дані правильні?**
   - Username, password без пробілів
   - Користувач має дозвіл на публікацію

3. **WiFi підключено?**
   ```cpp
   if (WiFi.status() != WL_CONNECTED) {
     // MQTT не підключиться
   }
   ```

4. **Переконніют з exponential backoff:**
   - 1-ва спроба: 5 сек
   - 2-га спроба: 10 сек
   - Максимум: 60 сек

### Q: API повертає 401 Unauthorized

```bash

# ✅ Правильно
curl -u aquasmart:aquasmart http://192.168.1.100/api/status
```

## Актуальний стан (оновлено 2026-01-30)

- LittleFS монтується централізовано в `src/main.cpp`. Якщо ви оновлювали код і бачите повідомлення `LittleFS Already Mounted!`, переконайтесь, що модулі не викликають `LittleFS.begin()` додатково.
- `/api/status` повертає поле `ssid` (фронтенд використовує `data.ssid`) і `rssi` як число (наприклад `-60`).
- Якщо ви бачите у серіалі помилки `open(): /littlefs/presets/... does not exist, no permits for creation` — виконайте повторне створення FS образу та залийте його командою `pio run -t uploadfs` щоб у образі були потрібні папки/файли (у проекті зараз автоматично створюється `presets/lighting/default.json`).

Якщо хочете — можу автоматично додати приклади `curl` для нових ендпоїнтів або оновити решту FAQ, щоб відобразити інші зміни API.

Або змініть пароль у `WebServerControl.cpp`

### Q: Веб-інтерфейс медленно завантажується
**A:** Причини:

1. **Слабкий WiFi сигнал** - коли RSSI < -70 dBm
2. **Велика JavaScript файл** - мініфікуйте CSS/JS
3. **Занадто багато запитів** - зберіть в один requestз

### Q: Як додати новий API endpoint?
**A:** Приклад у `WebServerControl.cpp`:

```cpp
server.on("/api/my-endpoint", HTTP_POST, [](AsyncWebServerRequest *request) {
  if (!request->authenticate(http_username.c_str(), http_password.c_str())) {
    return request->requestAuthentication();
  }
  
  if (request->hasParam("param1", true)) {
    String value = request->getParam("param1", true)->value();
    // Обробка запиту
    request->send(200, "text/plain", "OK");
  } else {
    request->send(400, "text/plain", "Missing param1");
  }
});
```

## OTA оновлення

### Q: OTA оновлення зависло на 50%
**A:** Спробуйте:

1. **Перезавантажити пристрій:**
   - Натиснути кнопку Reset
   - або вимкнути/включити живлення

2. **Завантажити через USB:**
   ```bash
   pio run --target upload
   ```

3. **Перевірити розмір прошивки:**
   - Максимум ~1.3 MB для ESP32
   - Поточний: ~1 MB (ОК)

### Q: Як повернути старшу версію?
**A:** Завантажте попередню прошивку:

```bash
git checkout HEAD~1
pio run --target upload
```

## Налагодження та логи

### Q: Як включити debug режим?
**A:** Оновіть `platformio.ini`:

```ini
build_flags =
    -DCORE_DEBUG_LEVEL=5  # VERBOSE
```

### Q: Де знаходяться логи?
**A:** Весь вихід йде на серійний монітор:

```bash
pio run --target monitor --baud 115200
```

### Q: Як експортувати логи для звіту про помилку?
**A:** Скопіюйте вихід і додайте до GitHub Issue:

```bash
pio run --target monitor > logs.txt 2>&1
# Запустіть відтворення помилки...
# Збережеться в logs.txt
```

## Продуктивність та оптимізація

### Q: Як зменшити використання пам'яті?
**A:** FreeRTOS завдання мають стеки:

```cpp
// main.cpp - зменшити розмір для завдань
xTaskCreatePinnedToCore(WiFiTask, "WiFiTask", 2048, nullptr, 2, &wifiTaskHandle, 1);
```

Мінімальні розміри:
- WiFi: 4096 (потребує більше для DNS)
- Light: 1024
- Temp: 1024
- MQTT: 2048
- Schedule: 2048

### Q: Який приблизний час запуску?
**A:** З холодного старту:
- Ініціалізація: ~500 мс
- WiFi підключення: 2-5 сек
- RTC синхронізація: 1-2 сек
- **Всього:** 5-10 сек до готовності
